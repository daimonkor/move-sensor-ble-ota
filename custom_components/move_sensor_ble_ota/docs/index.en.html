Quick start

From parts on the table to motion in Home Assistant. You need Home Assistant with the ESPHome Builder add-on, the Bluetooth integration and an ESPHome Bluetooth proxy near the sensor. Files are in the GitHub repository.

  1. Solder the XIAO ESP32-C3, SR602 PIR, SHT41 and LiPo as in the header of esphome/move_sensor_ble/base.yaml (pins, divider, LED, service switch).
  2. Copy the firmware into Home Assistant: everything from the repository's esphome/ → /config/esphome/.
  3. Secrets: secrets.example.yaml → /config/esphome/secrets.yaml (or add its lines to yours) and fill in your router Wi-Fi, a password for the sensor's own access point and move_sensor_ble_ota_key — any long random string, e.g. openssl rand -hex 16. The integration reads the same key from this file.
  4. Your sensor's file: move-sensor-ble-148f98.yaml → move-sensor-ble-new.yaml, set name / friendly_name. In ESPHome Builder: Install → Plug into this computer (USB, first flash only).
  5. Device ID: the last 6 hex digits of the sensor's Wi-Fi MAC (in the ESPHome install log and in the access point name MoveSensorBLE-XXXXXX). Rename the file to move-sensor-ble-<id>.yaml and put the id into name; builds over BLE look for exactly this file.
  6. Integration: the buttons in "Install" → Download → restart → Add integration → pick the sensor. The integration finds it by its BLE advertising — the BTHome integration is not needed. Leave OTA key empty.
  7. Signal on the sensor's site: in the sensor's file set ble_rssi_entity to the Signal entity of the Move Sensor BLE device, then Firmware → Install.
  8. Check: wave — Occupancy turns on and the LED flashes once; after Keep time it clears with two flashes. Settings status becomes In sync after the first wake-up.
From now on: firmware — the Firmware update entity (Install), no USB; settings and data — the Move Sensor BLE device and the sidebar panel. Wi-Fi is needed only in service mode (switch on D2, the LED flashes 3 times slowly): the sensor's site is at http://100.64.4.1/ on its access point.

How it works

The sensor spends almost all its time in deep sleep. When it wakes on PIR or on the telemetry timer, it advertises BTHome for ~4.5 s. The integration catches that window and does all the work in a single connection.

1
The sensor wakes upPIR or the "Climate report interval" timer. The advertisement becomes connectable.
2
HA catches the advertisementThrough the ESPHome Bluetooth proxy that hears the sensor best.
3
One connectionKey authentication → settings → firmware. While a client is connected, the sensor stays awake.
4
DoneThe sensor goes to sleep or reboots into the new firmware. Missed the window — wait for the next one.
There is work only when there is something to do: changed settings, a first read or a requested flash. Otherwise the integration touches neither the proxy nor the sensor. To get a window sooner, wave a hand in front of the sensor.

Install

Prerequisites: the Bluetooth integration in HA and at least one ESPHome Bluetooth proxy near the sensor (bluetooth_proxy: on an ESP32 — active connections are on by default). The sensor firmware must have ble_ota: in the bthome: block.

From Marketplace (HA 2026.11+)
  1. The Open your Home Assistant… repository button above opens the repository right in Marketplace (HACS before 2026.11). Without the button: Settings → Marketplace → Add from link.
  2. Paste the GitHub address of the integration repository, type Integration.
  3. Open Move Sensor BLE OTA → Download → restart HA.
  4. Then follow "Setup". Updates appear in Marketplace automatically with each new release.
Manually
  1. Copy the move_sensor_ble_ota folder to /config/custom_components/ (Samba / SSH / File editor).
  2. Restart Home Assistant.
  3. Then follow "Setup". To update, replace the folder and restart.
In HA 2026.11 HACS is built in as Marketplace. The repository format is the same as for HACS: public GitHub, hacs.json in the root, the integration in custom_components/move_sensor_ble_ota/, the icon in brand/, a GitHub release with the version number.
Updating. A new version is a GitHub release. HA shows it under Settings → Updates (to check right away: Marketplace → Move Sensor BLE OTA → ⋮ → Update information) → Update → restart HA. Entities, settings and statistics are kept.

Setup

  1. Settings → Devices & services → Add integration → Move Sensor BLE OTA.
  2. Bluetooth address — pick the sensor from the list of discovered ones HA currently hears, or enter it manually.
  3. OTA key — leave empty: move_sensor_ble_ota_key is taken from /config/esphome/secrets.yaml. If your ESPHome configs live elsewhere, enter the same key as in the firmware.
  4. Firmware folder — /config/esphome/ota by default.
  5. OTA password (Wi-Fi) and API encryption key (sensor firmware 1.4.0+) — stored in /config/esphome/secrets.yaml (move_sensor_ota_password, move_sensor_api_key), ESPHome uses them when building. Typed in — saved; empty — the current one stays, or the integration generates a random one and saves it if there is none. The integration puts the API key into the sensor’s ESPHome device itself — nothing to confirm after flashing. To view or change: ESPHome Builder → Secrets.
  6. Keep images — 3 by default (1–10): after every build and upload older .bin files in the firmware folder are deleted, so they do not pile up and bloat HA backups. The image being flashed or waiting for a window is never deleted. Change it in Configure → «Options»; how many are stored now — the «Stored images» row on the panel.
After adding
  • All sensor entities appear on one Move Sensor BLE device and in the sidebar panel.
  • On the first wake-up the integration reads the settings and version: Not read yet → Nothing pending.
  • To change the key or folder: integration page → Configure → "Options".
  • Documentation — the "Documentation" button (integration page) and "Visit" (device page).

Flashing

Easiest — the "Firmware" update entity → Install (v1.15; formerly the Build & flash button). A new version appears when the sensor YAML changed after the last flash. The integration compiles this sensor's YAML move-sensor-ble-<device id>.yaml (e.g. move-sensor-ble-148f98.yaml, since 1.13.1; shared firmware — move_sensor_ble/base.yaml) in the ESPHome Builder add-on (through the Supervisor, like HA itself), saves the .ota.bin to the firmware folder and flashes the sensor: in service mode at once over Wi-Fi, otherwise over BLE at the next window (if Wi-Fi drops it continues over BLE). Same via the move_sensor_ble_ota.build_and_flash service or POST /api/move_sensor_ble_ota/build. Outside HA — the /config/esphome/tools/ble_ota_flash.py script.
Manually, with your own file
  1. In ESPHome: Install → Manual download → OTA format (*.ota.bin). factory.bin works too — the app part is cut out automatically.
  2. Settings → Devices & services → Move Sensor BLE OTA → Configure → "Upload firmware (.bin)".
  3. Pick the file, keep "Start BLE flashing right away" checked.
  4. Wait for the sensor to wake up (or wave a hand). ~7 KB/s through a proxy — a 1.25 MB image takes ≈ 3 min.
Flash progress (the "Firmware" entity, /status attributes)
idle→ building %→ waiting→ connecting→ flashing %→ success
errorcancelled
building — only while building (Install, build_and_flash). After the build the OTA key inside the image is compared with the integration key — mismatch → error, no flashing. Cancel: service move_sensor_ble_ota.cancel or the panel button. After success it returns to idle and 0 % as soon as the sensor reports the new version (fallback timer 2 min). Connection lost → waiting, retry at the next window.
Only the application is updated over the air. The partition table (partitions_c3_4mb.csv) — USB only. The first firmware with BLE OTA support must also be flashed over USB or Wi-Fi (service mode).

Panel (v1.20)

The Move Sensor BLE panel in the sidebar has three tabs and uses only Home Assistant's own cards (tile cards with controls, badges, history graph) — nothing extra to install.

TabWhat is there
OverviewBadges: link, signal, last seen, settings status. «Needs attention» shows up only when something is wrong (low battery, no data, motion stuck, new firmware, settings not accepted). Four cards: Motion, Temperature, Humidity, Battery. Tap a card (or its gear) — a sheet with the 24 h history and the settings of that value; on a phone it slides up from the bottom and moves above the keyboard. Press and hold — Home Assistant's own dialog (full history, statistics); the chart icon in the sheet opens it too.
SettingsEveryday settings in three groups: Motion (Keep time, Motion LED), Temperature & humidity (Report interval), Battery (Capacity, Low level). Rarely used ones (Detect delay, offsets) — under «Show more». Numbers change with − / + buttons, the low level with a slider; only the capacity is typed (number pad).

Notifications (Settings › Repairs)

NotificationWhenGoes away
Battery is lowbattery at or below «Battery low level» (warning)by itself at level + 5 %
Sensor stopped, battery emptyno data for 3 × report interval (at least 15 min) and the last voltage was ≤ 3.55 V (error)when the sensor reports again
Sensor not reportingno data for as long, the battery was fine — range or power (error)when the sensor reports again
Motion stuck«detected» longer than «PIR stuck after» (warning)at «clear»

How long counts as «no data»: integration → Configure → Options → «Notify when no data for»: Auto (3 × report interval, at least 15 min) or 10 min … 2 h. It is never shorter than two report intervals, so a sleeping sensor gives no false alarm. With climate reports off (interval 0) the sensor may be quiet for hours without motion — no notification then. While the sensor is silent, «Motion stuck» is not reported: «detected» is just the last thing it sent.

Every new notification also fires the event move_sensor_ble_ota_issue (issue, name, address and the numbers from the text) — use it in an automation to get a push on your phone.

Less useful entities are off by default for new installs: Signal in dBm (Signal level in % stays), BLE TX power, brownout and crash counters. Turn them on in the entity settings if you need them.

Moving to a new Home Assistant

Via a full HA backup — easiest
  1. Old HA: Settings → System → Backups → full backup.
  2. New HA: on first start choose "Restore from backup".
  3. Everything moves: the integration folder, the entry with address and key, saved settings (.storage/move_sensor_ble_ota.*), firmware in /config/esphome/ota, secrets.yaml.
  4. Check that the ESPHome Bluetooth proxy is connected to the new HA and the sensor is visible.
From scratch, without a backup
  1. Connect the Bluetooth proxy to the new HA (ESPHome integration). The BTHome integration is not needed.
  2. Install the integration — from Marketplace or manually (see "Install").
  3. Key: copy the move_sensor_ble_ota_key line to /config/esphome/secrets.yaml of the new HA or enter it when adding. Without it the sensor refuses ("not authorized").
  4. Add the integration with the same Bluetooth address. Settings are read from the sensor at the first wake-up.
The key is the only thing that cannot be recovered from the sensor. Keep it with your ESPHome configs. If the key is lost, change it in secrets.yaml and flash over USB or Wi-Fi (service mode).

Backup and rollback (v1.18). The «Firmware» update dialog has a Release notes / changelog link (firmware CHANGELOG on GitHub) and a Backup toggle: before the build, the firmware currently on the sensor and a copy of its YAML are saved to <firmware folder>/backup/ (last 3; .bin cleanup leaves them alone). If the current firmware image is not in the folder (flashed from ESPHome Builder or removed by cleanup), Install with the toggle stops with an error. Rollback — service move_sensor_ble_ota.rollback: same path (Wi-Fi in service mode, otherwise BLE); afterwards «Firmware» offers the current YAML again. Attribute backup shows the latest copy.

GATT protocol

Service 6d730001-626c-6f74-4d6f-766553656e73. All numbers are little-endian.

CharacteristicCommands
…0002 CTRL
write + notify		 HELLO nonce · AUTH HMAC · INFO version · GET/SET settings · BEGIN size+CRC · STATUS · END · ABORT
…0003 DATA
write without response		 offset:u32 + data (≤ 240 B), 4096 B blocks, an ACK on CTRL after each; every 4th packet with response

Full description — in the header of components/bthome/ble_ota.h (firmware) and const.py (integration).

Troubleshooting

Stuck in waitingThe sensor doesn't wake up or the proxy doesn't hear it. Wave a hand; check that a proxy with bluetooth_proxy: (active connections) is nearby.
Loop connecting → flashing → waitingThe sensor drops the link. Check the sensor log in service mode (tag ble_ota) for the reason.
Settings status: error"invalid state/command" — the sensor firmware lacks the settings commands. Wrong key — "not authorized".
"battery below threshold"Charge the sensor or change min_battery in the YAML.
