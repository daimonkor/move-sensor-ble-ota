Move Sensor BLE OTA

Прошивка по повітрю та віддалені налаштування для батарейного датчика руху — по Bluetooth, через Bluetooth-проксі ESPHome. Датчик спить, Wi-Fi не потрібен.

Швидкий старт

Від деталей на столі до руху в Home Assistant. Потрібні Home Assistant з аддоном ESPHome Builder, інтеграція Bluetooth і Bluetooth-проксі ESPHome поруч із датчиком. Файли — у репозиторії на GitHub.

  1. Спаяти XIAO ESP32-C3, PIR SR602, SHT41 і LiPo за шапкою esphome/move_sensor_ble/base.yaml (піни, дільник, LED, сервісний перемикач).
  2. Скопіювати прошивку у Home Assistant: усе з esphome/ репозиторію → /config/esphome/.
  3. Секрети: secrets.example.yaml → /config/esphome/secrets.yaml (або дописати рядки у свій) і заповнити Wi-Fi роутера, пароль своєї точки доступу датчика і move_sensor_ble_ota_key — будь-який довгий випадковий рядок, наприклад openssl rand -hex 16. Інтеграція бере той самий ключ із цього файлу.
  4. Файл датчика: move-sensor-ble-148f98.yaml → move-sensor-ble-new.yaml, виправити name / friendly_name. У ESPHome Builder: Install → Plug into this computer (USB, лише перший раз).
  5. Device ID — останні 6 hex-цифр MAC Wi-Fi датчика (у лозі встановлення ESPHome та в імені точки доступу MoveSensorBLE-XXXXXX). Перейменувати файл на move-sensor-ble-<id>.yaml і вписати id у name: збірка по BLE шукає саме цей файл.
  6. Інтеграція: кнопки у «Встановленні» → Завантажити → перезапуск → Додати інтеграцію → вибрати датчик. Інтеграція знаходить його сама за BLE-рекламою — окрема інтеграція BTHome не потрібна. Поле Ключ OTA залишити порожнім.
  7. Сигнал на сайті датчика: у файлі датчика ble_rssi_entity = сутність Signal пристрою Move Sensor BLE, потім Firmware → Встановити.
  8. Перевірка: помахати — Occupancy вмикається, LED блимає 1 раз; через Keep time — «вільно» і 2 спалахи. Settings status після першого пробудження — In sync.
Далі прошивка — сутність Firmware («Встановити»), без USB; налаштування й дані — пристрій Move Sensor BLE і панель у меню. Wi-Fi потрібен лише в сервісному режимі (перемикач на D2, LED — 3 повільні спалахи): сайт датчика — http://100.64.4.1/ на його точці доступу.

Як це працює

Датчик майже весь час у глибокому сні. Прокинувшись від PIR або за таймером телеметрії, він ~4,5 с надсилає BTHome-рекламу. Інтеграція ловить це вікно і за одне підключення робить усю роботу.

1
Датчик прокидаєтьсяPIR або таймер «Climate report interval». Реклама стає такою, до якої можна підключитися.
2
HA ловить рекламуЧерез Bluetooth-проксі ESPHome — той, що чує датчик найкраще.
3
Одне підключенняАвторизація ключем → налаштування → прошивка. Поки клієнт підключений, датчик не спить.
4
ГотовоДатчик засинає або перезавантажується в нову прошивку. Не встигли — чекаємо наступне вікно.
Робота з’являється, лише якщо є що робити: змінені налаштування, перше читання або запитана прошивка. Інакше інтеграція не чіпає ні проксі, ні датчик. Пришвидшити вікно — помахати рукою перед датчиком.

Встановлення

Що потрібно заздалегідь: інтеграція Bluetooth у HA і хоча б один Bluetooth-проксі ESPHome поруч із датчиком (bluetooth_proxy: на ESP32 — активні підключення ввімкнені за замовчуванням). На датчику — прошивка з ble_ota: у блоці bthome:.

З Marketplace (HA 2026.11+)
  1. Кнопка Open your Home Assistant… repository вище відкриє репозиторій просто в Marketplace (до 2026.11 — у HACS). Без кнопки: Налаштування → Marketplace → Додати за посиланням.
  2. Вставити адресу GitHub-репозиторію інтеграції, тип Integration.
  3. Відкрити Move Sensor BLE OTA → Встановити → перезапустити HA.
  4. Далі — «Як налаштувати». Оновлення прийдуть у Marketplace самі з новим релізом.
Вручну
  1. Скопіювати теку move_sensor_ble_ota у /config/custom_components/ (Samba / SSH / File editor).
  2. Перезапустити Home Assistant.
  3. Далі — «Як налаштувати». Оновлювати — заміною теки й перезапуском.
У HA 2026.11 HACS вбудований у систему як Marketplace. Репозиторій для нього — той самий формат, що був у HACS: публічний GitHub, hacs.json у корені, інтеграція в custom_components/move_sensor_ble_ota/, іконка в brand/, GitHub-реліз із номером версії.
Оновлення. Нова версія — це GitHub-реліз. HA покаже її в Налаштування → Оновлення (перевірити одразу: Marketplace → Move Sensor BLE OTA → ⋮ → Оновити інформацію) → Оновити → перезапустити HA. Сутності, налаштування й статистика зберігаються.

Як налаштувати

  1. Налаштування → Пристрої та служби → Додати інтеграцію → Move Sensor BLE OTA.
  2. Bluetooth-адреса — вибрати датчик зі списку знайдених (їх зараз чує HA) або вписати вручну.
  3. Ключ OTA — залишити порожнім: візьметься move_sensor_ble_ota_key з /config/esphome/secrets.yaml. Якщо конфіги ESPHome лежать в іншому місці — вписати той самий ключ, що в прошивці.
  4. Тека прошивок — за замовчуванням /config/esphome/ota.
  5. Пароль OTA по Wi-Fi і Ключ шифрування API (прошивка датчика 1.4.0+) — зберігаються в /config/esphome/secrets.yaml (move_sensor_ota_password, move_sensor_api_key), ESPHome бере їх під час збірки. Ввів — збережеться; порожньо — залишиться поточний, а якщо його немає, інтеграція згенерує випадковий і збереже. Ключ API інтеграція сама вписує в ESPHome-пристрій датчика — після прошивки нічого підтверджувати не треба. Переглянути або змінити: ESPHome Builder → Secrets.
  6. Зберігати образів — за замовчуванням 3 (1–10): після кожної збірки та завантаження старі .bin у теці прошивок видаляються, щоб вони не накопичувалися й не роздували резервні копії HA. Образ, який прошивається або чекає вікна, не видаляється. Змінюється в Налаштувати → «Параметри»; скільки зберігається зараз — рядок «Stored images» на панелі.
Після додавання
  • Усі сутності датчика з’являться на одному пристрої Move Sensor BLE і на панелі в меню.
  • Під час першого пробудження інтеграція прочитає налаштування та версію: Not read yet → Nothing pending.
  • Змінити ключ або теку: сторінка інтеграції → Налаштувати → «Параметри».
  • Документація — кнопки «Документація» (сторінка інтеграції) і «Відвідати» (сторінка пристрою).

Як прошивати

Найпростіше — сутність оновлення «Firmware» → «Встановити» (v1.15; раніше кнопка Build & flash). Нова версія з’являється, коли YAML датчика змінено після останньої прошивки. Інтеграція сама збере YAML цього датчика move-sensor-ble-<device id>.yaml (напр. move-sensor-ble-148f98.yaml, з 1.13.1; спільна прошивка — move_sensor_ble/base.yaml) в аддоні ESPHome Builder (через Supervisor, як сам HA), покладе .ota.bin у теку прошивок і прошиє датчик: у сервісному режимі — одразу по Wi-Fi, інакше по BLE в найближче вікно (обірвався Wi-Fi — продовжить по BLE). Те саме — сервіс move_sensor_ble_ota.build_and_flash або POST /api/move_sensor_ble_ota/build. Поза HA — скрипт /config/esphome/tools/ble_ota_flash.py.
Вручну, своїм файлом
  1. У ESPHome: Install → Manual download → OTA format (*.ota.bin). Підійде і factory.bin — застосунок виріжеться сам.
  2. Налаштування → Пристрої та служби → Move Sensor BLE OTA → Налаштувати → «Завантажити прошивку (.bin)».
  3. Вибрати файл, залишити галочку «Одразу запустити прошивку по BLE».
  4. Дочекатися пробудження датчика (або помахати рукою). ~7 КБ/с через проксі — образ 1,25 МБ ≈ 3 хв.
Хід прошивки (сутність «Firmware», атрибути /status)
idle→ building %→ waiting→ connecting→ flashing %→ success
errorcancelled
building — лише під час збірки («Встановити», build_and_flash). Після збірки ключ OTA в образі звіряється з ключем інтеграції — не збігся → помилка, прошивка не починається. Скасування — служба move_sensor_ble_ota.cancel або кнопка на панелі. Після success — одразу idle і 0 %, щойно датчик відповів новою версією (запасний таймер 2 хв). Обрив зв’язку → waiting, повтор у наступне вікно.
По повітрю змінюється лише застосунок. Таблиця розділів (partitions_c3_4mb.csv) — лише по USB. Першу прошивку з підтримкою BLE OTA теж залити по USB або Wi-Fi (сервісний режим).

Панель (v1.20)

Панель Move Sensor BLE у бічному меню — три таби, лише стандартні картки Home Assistant (tile з елементами керування, значки, графік історії). Нічого доінсталювати не треба.

З v1.24 тексти панелі (таби, заголовки, підказки, «Потребує уваги») йдуть мовою Home Assistant (Профіль › Мова): російська, українська, для решти — англійська. Імена сутностей лишаються англійськими.

З v1.26 (прошивка 1.9.0+): заряджання визначає сам датчик — бібліотека li_battery (charge_detect) за стрибком напруги спокою вгору або напругою біля максимуму, доки вона не піде вниз, — і шле прапорець бітом 7 останнього байта свого блоку реклами (окреме поле BTHome не влазить: пакет 31 з 31 байта). На зарядці картка Battery зелена з іконкою заряджання та міткою «Заряджається», попередження про низький заряд приховане; атрибут charging у сутності Battery. З v1.26.1 на зарядці в заголовку панелі, поруч зі зв’язком і сигналом, з’являється значок «Заряджається» з відсотком.

З v1.27: інтеграція знає, якою версією ESPHome та ESP-IDF (платформа esp32) зібрано прошивку на датчику (читає з образу), і раз на 30 хвилин питає в Supervisor версію аддона ESPHome Builder. Оновили ESPHome Builder — «Firmware» пропонує оновлення, а на панелі (Огляд → «Потребує уваги» та Розширені → Прошивка) з’являється опис і кнопка «Оновити» (натиснути двічі): перезбирання новою версією та прошивка через Wi-Fi одразу, якщо датчик у сервісному режимі, інакше через Bluetooth при найближчому пробудженні. Перед прошивкою зберігається резервна копія. Атрибути esphome_flashed, esp_idf_flashed, esphome_builder, esphome_update у сутності Firmware.

З v1.28: у шапці панелі Move Sensor BLE видно версію інтеграції (якщо в Marketplace є нова — «v1.28.0 → v1.29.0» помаранчевим), а натискання на неї відкриває нову вкладку «Про доповнення»: версія та наявність оновлення, версії прошивки датчика, ESPHome/ESP-IDF, якими її зібрано, ESPHome Builder і Home Assistant, посилання на документацію, релізи, зміни прошивки, вихідний код і налаштування інтеграції, а також «Що нового» встановленої версії (опис релізу з GitHub).

З v1.29: нова версія інтеграції з’являється в Marketplace сама. Marketplace перевіряє встановлені користувацькі репозиторії лише раз на 48 годин, тому інтеграція щогодини (і через 2 хвилини після старту HA) дивиться останній реліз на GitHub і, якщо він новіший за встановлений, оновлює інформацію про репозиторій у Marketplace — як пункт «Оновити інформацію». Далі оновлення підсвічується на панелі (з v1.28.1). Відкрита вкладка панелі після оновлення інтеграції один раз перезавантажується сама, щоб не показувати стару версію.

З v1.29.2: на вкладці «Про доповнення» є перемикач «Автооновлення» (як в аддонів Home Assistant, типово вимкнений; сутність switch.…_auto_update_integration). Нова версія показується завжди, а з автооновленням ще й встановлюється сама під час найближчої перевірки (щогодини) — після цього приходить сповіщення, і Marketplace показує, що потрібен перезапуск: нова версія почне працювати після перезапуску Home Assistant. Також виправлено автовікно реклами після чистого встановлення: без історії сигналу воно стартує з вікон, що вже стоять на датчику, і вкорочує їх лише за повною вибіркою з 10 пакетів із запасом 3 дБ.

Довге натискання — стандартне вікно Home Assistant (повна історія, статистика); його ж відкриває іконка графіка в шторці.

Незворотні дії (відкат, скидання Wi-Fi) просять підтвердження. Нова сутність інтеграції без свого місця потрапляє в Diagnostics.

Сповіщення (Налаштування › Ремонт)

СповіщенняКолиЗникає
Батарея сідаєзаряд не вище «Battery low level» (попередження)саме на порозі + 5 %
Датчик зупинився, батарея сіланемає даних довше за 3 інтервали клімату (щонайменше 15 хв), остання напруга ≤ 3,55 В (помилка)коли датчик знову на зв'язку
Датчик не виходить на зв'язокнемає даних стільки ж, а батарея була в порядку — зв'язок або живлення (помилка)коли датчик знову на зв'язку
Рух «залип»«зайнято» довше за «PIR stuck after» (попередження)при «вільно»

Скільки вважати «немає даних»: інтеграція → Налаштувати → Параметри → «Сообщать, если нет данных» (Notify when no data for): Авто (3 × інтервал клімату, щонайменше 15 хв) або 10 хв … 2 год. Не коротше за два інтервали клімату — сплячий датчик не дає хибних тривог. Якщо звіти клімату вимкнені (інтервал 0), без руху датчик може мовчати годинами — тоді сповіщення немає. Поки датчик мовчить, «рух залип» не повідомляється: «зайнято» — це просто його остання посилка.

Кожне нове сповіщення — ще й подія move_sensor_ble_ota_issue (issue, name, address і числа з тексту) — повісьте на неї автоматизацію з пушем на телефон.

Малокорисні сутності при новому встановленні вимкнені: Signal у дБм (Signal level у % лишається), BLE TX power, лічильники brownout і збоїв. Потрібні — увімкніть у налаштуваннях сутності.

Через повну резервну копію HA — найпростіше
  1. Старий HA: Налаштування → Система → Резервні копії → повна копія.
  2. Новий HA: під час першого запуску «Відновити з резервної копії».
  3. Переїде все: тека інтеграції, запис з адресою та ключем, збережені налаштування (.storage/move_sensor_ble_ota.*), прошивки в /config/esphome/ota, secrets.yaml.
  4. Перевірити, що Bluetooth-проксі ESPHome підключений до нового HA і датчик видно.
Начисто, без резервної копії
  1. Підключити до нового HA Bluetooth-проксі (інтеграція ESPHome). Інтеграція BTHome не потрібна.
  2. Встановити інтеграцію — з Marketplace або вручну (розділ «Встановлення»).
  3. Ключ: перенести рядок move_sensor_ble_ota_key у /config/esphome/secrets.yaml нового HA або вписати його під час додавання. Без нього датчик не пустить («немає авторизації»).
  4. Додати інтеграцію з тією самою Bluetooth-адресою. Налаштування прочитаються з датчика під час першого пробудження.
Ключ — єдине, що не можна відновити з датчика. Зберігай його разом з ESPHome-конфігами. Якщо ключ втрачено — змінити його в secrets.yaml і залити прошивку по USB або Wi-Fi (сервісний режим).

Сутності

v1.15: один пристрій Move Sensor BLE — дані й налаштування датчика незалежно від каналу (BLE або Wi-Fi). Копії в ESPHome-пристрої та BTHome (якщо його додано) приховані (не вимкнені). Панель Move Sensor BLE у боковому меню.

Дані датчика (v1.15)

Occupancy / Temperature / Humidity / Battery / VoltagesensorЗ будь-якого каналу: BLE (реклама BTHome) або Wi-Fi (ESPHome-пристрій датчика) — перемагає найсвіжіше. В атрибутах — джерело та час
Link / Signal / Signal levelsensorКанал зв’язку: wifi — ESPHome API підключений (WiFi на датчику ввімкнений), інакше ble. Signal — RSSI цього каналу, дБм; Signal level — те саме у % (−90 дБм = 0 %, −30 дБм = 100 %)
Приховані копіїautoТі самі сутності в ESPHome- і BTHome-пристрої приховані (мітка Move Sensor BLE), продовжують працювати. В ESPHome-пристрої на виду лише Wi-Fi і сервісний режим. Показати окрему копію — на сторінці пристрою HA, «+N прихованих об’єктів»; прибрати панель з меню — «Змінити бічну панель» у HA. Видалення інтеграції повертає приховане

Прошивка

FirmwareupdateЗамість Flash / Build & flash / Cancel / OTA status / OTA progress / Firmware version. В «Оновленнях» — «Move Sensor BLE firmware»: встановлена «build 16.11 13:48», нова «new build · YAML changed …». «Встановити» — збірка, перевірка ключа OTA, прошивка по Wi-Fi одразу (сервісний режим) або по BLE в найближче пробудження; обірвався Wi-Fi — продовжить по BLE; переживає перезапуск HA; та сама збірка, що вже на датчику, повторно не прошивається; Last flash — час, канал, тривалість, швидкість; «Примітки до випуску» — які файли прошивки змінені з прошитої збірки та порядковий diff (secrets.yaml не показується, ключі й паролі — ***). Версія прошивки та «що нового» — з esphome/move_sensor_ble/CHANGELOG.md (розділи «## 1.4.0 — дата» з «Додано / Виправлено / Змінено», як в аддонів): показуються розділи, яких не було в прошитій збірці; немає запису — короткий переказ «параметр: було → стало». Зміна лише CHANGELOG нову прошивку не пропонує. З прошивки 1.4.0 версію повідомляє сам датчик (по BLE, «1.4.0 v…»): «що нового» — усі розділи CHANGELOG новіші за неї. Пароль ESPHome OTA для прошивки по Wi-Fi (прошивка 1.4.0+) інтеграція бере з move_sensor_ota_password у secrets.yaml. Прошивка «Встановити» в самому ESPHome Builder ключ не перевіряє. На панелі в розділі Firmware (v1.18.1): OTA status — етап на всіх кроках («Building 37 %», «Waiting for sensor wake», «Connecting», «Flashing 70 %», «Success», «Error: …», «Idle»; у самої «Firmware» відсоток видно лише під час прошивки); кнопки Install (збірка й прошивка з резервною копією, з підтвердженням), Build (лише зібрати — перевірка конфігу без прошивки), рядок Backup (остання копія) і Roll back (прошити її назад, з підтвердженням), Cancel. Після прошивки версія у «Firmware» оновлюється одразу, як датчик її повідомив

Лише свій образзвірка project_name; CRC-32 і перевірка ESP-IDF
Поріг батареїнижче 30 % OTA відхиляється
Відкатне пройшла safe_mode 15 с — завантажувач поверне стару
Резервна копія та відкат (v1.18). У вікні оновлення «Firmware» є посилання «Список змін» (CHANGELOG прошивки на GitHub) і перемикач «Резервна копія»: перед збиранням прошивка, що зараз на датчику, і копія її YAML зберігаються в <тека прошивок>/backup/ (останні 3, прибирання .bin їх не чіпає). Якщо образу поточної прошивки в теці немає (прошито з ESPHome Builder або видалено прибиранням) — «Встановити» з перемикачем зупиниться з помилкою. Відкат — сервіс move_sensor_ble_ota.rollback: тим самим шляхом (Wi-Fi в сервісному режимі, інакше BLE), після нього «Firmware» знову запропонує поточний YAML. Атрибут backup — яка копія остання.
