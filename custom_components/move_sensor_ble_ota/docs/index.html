Move Sensor BLE OTA

Прошивка по воздуху и удалённые настройки для батарейного датчика движения — по Bluetooth, через Bluetooth-прокси ESPHome. Датчик спит, Wi-Fi не нужен.

Как это работает

Датчик почти всё время в глубоком сне. Проснувшись от PIR или по таймеру телеметрии, он ~4,5 с шлёт BTHome-рекламу. Интеграция ловит это окно и за одно подключение делает всю работу.

1
Датчик просыпаетсяPIR или таймер «Climate report interval». Реклама становится подключаемой.
2
HA ловит рекламуЧерез Bluetooth-прокси ESPHome — тот, что слышит датчик лучше всех.
3
Одно подключениеАвторизация ключом → настройки → прошивка. Пока клиент подключён, датчик не спит.
4
ГотовоДатчик засыпает или перезагружается в новую прошивку. Не успели — ждём следующее окно.
Работа появляется, только если есть что делать: изменённые настройки, первое чтение или запрошенная прошивка. Иначе интеграция не трогает ни прокси, ни датчик. Ускорить окно — помахать рукой перед датчиком.

Установка

Что нужно заранее: интеграция Bluetooth в HA и хотя бы один Bluetooth-прокси ESPHome рядом с датчиком (bluetooth_proxy: на ESP32 — активные подключения включены по умолчанию). На датчике — прошивка с ble_ota: в блоке bthome:.

Из Marketplace (HA 2026.11+)
  1. Настройки → Marketplace → Добавить по ссылке (или «Пользовательские репозитории»).
  2. Вставить адрес GitHub-репозитория интеграции, тип Integration.
  3. Открыть Move Sensor BLE OTA → Установить → перезапустить HA.
  4. Дальше — «Как настроить». Обновления придут в Marketplace сами при новом релизе.
Вручную
  1. Скопировать папку move_sensor_ble_ota в /config/custom_components/ (Samba / SSH / File editor).
  2. Перезапустить Home Assistant.
  3. Дальше — «Как настроить». Обновлять — заменой папки и перезапуском.
В HA 2026.11 HACS встроен в систему как Marketplace. Репозиторий для него — тот же формат, что был у HACS: публичный GitHub, hacs.json в корне, интеграция в custom_components/move_sensor_ble_ota/, иконка в brand/, GitHub-релиз с номером версии.

Как настроить

  1. Настройки → Устройства и службы → Добавить интеграцию → Move Sensor BLE OTA.
  2. Bluetooth-адрес — выбрать датчик из списка BTHome-устройств (их сейчас слышит HA) или вписать вручную.
  3. Ключ OTA — оставить пустым: возьмётся move_sensor_ble_ota_key из /config/esphome/secrets.yaml. Если конфиги ESPHome лежат в другом месте — вписать тот же ключ, что в прошивке.
  4. Папка прошивок — по умолчанию /config/esphome/ota.
После добавления
  • Сущности «… (BLE)» появятся на странице того же устройства, что и BTHome-датчик.
  • При первом пробуждении интеграция прочитает настройки и версию: unknown → applied.
  • Поменять ключ или папку: страница интеграции → Настроить → «Параметры».
  • Документация — кнопки «Документация» (страница интеграции) и «Посетить» (страница устройства).

Как прошивать

Проще всего — одной кнопкой «Build & flash firmware (BLE)». Интеграция сама соберёт move-sensor-ble.yaml в аддоне ESPHome Builder (через Supervisor, как сам HA), положит .ota.bin в папку прошивок и прошьёт датчик по BLE в ближайшее окно. То же — сервис move_sensor_ble_ota.build_and_flash или POST /api/move_sensor_ble_ota/build. Снаружи HA — скрипт /config/esphome/tools/ble_ota_flash.py.
Вручную, своим файлом
  1. В ESPHome: Install → Manual download → OTA format (*.ota.bin). Подойдёт и factory.bin — приложение вырежется само.
  2. Настройки → Устройства и службы → Move Sensor BLE OTA → Настроить → «Загрузить прошивку (.bin)».
  3. Выбрать файл, оставить галочку «Сразу запустить прошивку по BLE».
  4. Дождаться пробуждения датчика (или помахать рукой). ~7 КБ/с через прокси — образ 1,25 МБ ≈ 3 мин.
Статусы «OTA status»
idle→ building %→ waiting→ connecting→ flashing %→ success
errorcancelled
building — только у «Build & flash». После success — сразу idle и 0 %, как только датчик ответил новой версией (запасной таймер 2 мин). Обрыв связи → waiting, повтор в следующее окно.
По воздуху меняется только приложение. Таблица разделов (partitions_c3_4mb.csv) — только по USB. Первую прошивку с поддержкой BLE OTA тоже залить по USB или Wi-Fi (сервисный режим).

Перенос на новый Home Assistant

Через полный бэкап HA — проще всего
  1. Старый HA: Настройки → Система → Резервные копии → полная копия.
  2. Новый HA: при первом запуске «Восстановить из резервной копии».
  3. Переедет всё: папка интеграции, запись с адресом и ключом, сохранённые настройки (.storage/move_sensor_ble_ota.*), прошивки в /config/esphome/ota, secrets.yaml.
  4. Проверить, что Bluetooth-прокси ESPHome подключён к новому HA и BTHome-датчик виден.
Начисто, без бэкапа
  1. Подключить к новому HA Bluetooth-прокси (интеграция ESPHome) и добавить датчик в BTHome.
  2. Установить интеграцию — из Marketplace или вручную (раздел «Установка»).
  3. Ключ: перенести строку move_sensor_ble_ota_key в /config/esphome/secrets.yaml нового HA или вписать его при добавлении. Без него датчик не пустит («нет авторизации»).
  4. Добавить интеграцию с тем же Bluetooth-адресом. Настройки прочитаются с датчика при первом пробуждении.
Ключ — единственное, что нельзя восстановить с датчика. Храни его вместе с ESPHome-конфигами. Если ключ потерян — сменить его в secrets.yaml и залить прошивку по USB или Wi-Fi (сервисный режим).

Протокол GATT

Сервис 6d730001-626c-6f74-4d6f-766553656e73. Все числа little-endian.

ХарактеристикаКоманды
…0002 CTRL
write + notify		 HELLO nonce · AUTH HMAC · INFO версия · GET/SET настройки · BEGIN размер+CRC · STATUS · END · ABORT
…0003 DATA
write without response		 offset:u32 + данные (≤ 240 Б), блоки 4096 Б, после каждого — ACK в CTRL; каждый 4-й пакет с подтверждением

Полное описание — в шапке components/bthome/ble_ota.h (прошивка) и const.py (интеграция).

Диагностика

Долго waitingДатчик не просыпается или прокси его не слышит. Помахать рукой; проверить, что прокси с bluetooth_proxy: (активные подключения) рядом.
Цикл connecting → flashing → waitingДатчик рвёт связь. Смотреть лог датчика в сервисном режиме (тег ble_ota) — там причина.
Settings status: error«неверное состояние/команда» — на датчике прошивка без команд настроек. Неверный ключ — «нет авторизации».
«батарея ниже порога»Зарядить датчик или поменять min_battery в YAML.
