Быстрый старт

От деталей на столе до движения в Home Assistant. Нужны Home Assistant с аддоном ESPHome Builder, интеграция Bluetooth и Bluetooth-прокси ESPHome рядом с датчиком. Файлы — в репозитории на GitHub.

  1. Спаять XIAO ESP32-C3, PIR SR602, SHT41 и LiPo по шапке esphome/move_sensor_ble/base.yaml (пины, делитель, LED, сервисный переключатель).
  2. Скопировать прошивку в Home Assistant: всё из esphome/ репозитория → /config/esphome/.
  3. Секреты: secrets.example.yaml → /config/esphome/secrets.yaml (или дописать строки в свой) и заполнить Wi-Fi роутера, пароль своей точки доступа датчика и move_sensor_ble_ota_key — любая длинная случайная строка, например openssl rand -hex 16. Интеграция берёт тот же ключ из этого файла.
  4. Файл датчика: move-sensor-ble-148f98.yaml → move-sensor-ble-new.yaml, поправить name / friendly_name. В ESPHome Builder: Install → Plug into this computer (USB, только первый раз).
  5. Device ID — последние 6 hex-цифр MAC Wi-Fi датчика (в логе установки ESPHome и в имени точки доступа MoveSensorBLE-XXXXXX). Переименовать файл в move-sensor-ble-<id>.yaml и вписать id в name: сборка по BLE ищет именно этот файл.
  6. Интеграция: кнопки в «Установке» → Скачать → перезапуск → Добавить интеграцию → выбрать датчик. Интеграция находит его сама по BLE-рекламе — отдельная интеграция BTHome не нужна. Поле Ключ OTA оставить пустым.
  7. Сигнал на сайте датчика: в файле датчика ble_rssi_entity = сущность Signal устройства Move Sensor BLE, затем Firmware → Установить.
  8. Проверка: помахать — Occupancy включается, LED мигает 1 раз; через Keep time — «свободно» и 2 вспышки. Settings status после первого пробуждения — In sync.
Дальше прошивка — сущность Firmware («Установить»), без USB; настройки и данные — устройство Move Sensor BLE и панель в меню. Wi-Fi нужен только в сервисном режиме (переключатель на D2, LED — 3 медленные вспышки): сайт датчика — http://100.64.4.1/ на его точке доступа.

Как это работает

Датчик почти всё время в глубоком сне. Проснувшись от PIR или по таймеру телеметрии, он ~4,5 с шлёт BTHome-рекламу. Интеграция ловит это окно и за одно подключение делает всю работу.

1
Датчик просыпаетсяPIR или таймер «Climate report interval». Реклама становится подключаемой.
2
HA ловит рекламуЧерез Bluetooth-прокси ESPHome — тот, что слышит датчик лучше всех.
3
Одно подключениеАвторизация ключом → настройки → прошивка. Пока клиент подключён, датчик не спит.
4
ГотовоДатчик засыпает или перезагружается в новую прошивку. Не успели — ждём следующее окно.
Работа появляется, только если есть что делать: изменённые настройки, первое чтение или запрошенная прошивка. Иначе интеграция не трогает ни прокси, ни датчик. Ускорить окно — помахать рукой перед датчиком.

Установка

Что нужно заранее: интеграция Bluetooth в HA и хотя бы один Bluetooth-прокси ESPHome рядом с датчиком (bluetooth_proxy: на ESP32 — активные подключения включены по умолчанию). На датчике — прошивка с ble_ota: в блоке bthome:.

Из Marketplace (HA 2026.11+)
  1. Кнопка Open your Home Assistant… repository выше откроет репозиторий прямо в Marketplace (до 2026.11 — в HACS). Без кнопки: Настройки → Marketplace → Добавить по ссылке.
  2. Вставить адрес GitHub-репозитория интеграции, тип Integration.
  3. Открыть Move Sensor BLE OTA → Установить → перезапустить HA.
  4. Дальше — «Как настроить». Обновления придут в Marketplace сами при новом релизе.
Вручную
  1. Скопировать папку move_sensor_ble_ota в /config/custom_components/ (Samba / SSH / File editor).
  2. Перезапустить Home Assistant.
  3. Дальше — «Как настроить». Обновлять — заменой папки и перезапуском.
В HA 2026.11 HACS встроен в систему как Marketplace. Репозиторий для него — тот же формат, что был у HACS: публичный GitHub, hacs.json в корне, интеграция в custom_components/move_sensor_ble_ota/, иконка в brand/, GitHub-релиз с номером версии.
Обновление. Новая версия — это GitHub-релиз. HA покажет её в Настройки → Обновления (проверить сразу: Marketplace → Move Sensor BLE OTA → ⋮ → Обновить информацию) → Обновить → перезапустить HA. Сущности, настройки и статистика сохраняются.

Как настроить

  1. Настройки → Устройства и службы → Добавить интеграцию → Move Sensor BLE OTA.
  2. Bluetooth-адрес — выбрать датчик из списка найденных (их сейчас слышит HA) или вписать вручную.
  3. Ключ OTA — оставить пустым: возьмётся move_sensor_ble_ota_key из /config/esphome/secrets.yaml. Если конфиги ESPHome лежат в другом месте — вписать тот же ключ, что в прошивке.
  4. Папка прошивок — по умолчанию /config/esphome/ota.
  5. Пароль OTA по Wi-Fi и Ключ шифрования API (прошивка датчика 1.4.0+) — хранятся в /config/esphome/secrets.yaml (move_sensor_ota_password, move_sensor_api_key), ESPHome берёт их при сборке. Ввёл — сохранится; пусто — останется текущий, а если его нет, интеграция сгенерирует случайный и сохранит. Ключ API интеграция сама вписывает в ESPHome-устройство датчика — после прошивки подтверждать ничего не нужно. Посмотреть или поменять: ESPHome Builder → Secrets.
  6. Хранить образов — по умолчанию 3 (1–10): после каждой сборки и загрузки старые .bin в папке прошивок удаляются, чтобы они не копились и не раздували бэкапы HA. Образ, который шьётся или ждёт окна, не удаляется. Меняется в Настроить → «Параметры»; сколько хранится сейчас — строка «Stored images» на панели.
После добавления
  • Все сущности датчика появятся на одном устройстве Move Sensor BLE и на панели в меню.
  • При первом пробуждении интеграция прочитает настройки и версию: Not read yet → Nothing pending.
  • Поменять ключ или папку: страница интеграции → Настроить → «Параметры».
  • Документация — кнопки «Документация» (страница интеграции) и «Посетить» (страница устройства).

Как прошивать

Проще всего — сущность обновления «Firmware» → «Установить» (v1.15; раньше кнопка Build & flash). Новая версия появляется, когда YAML датчика изменён после последней прошивки. Интеграция сама соберёт YAML этого датчика move-sensor-ble-<device id>.yaml (напр. move-sensor-ble-148f98.yaml, с 1.13.1; общая прошивка — move_sensor_ble/base.yaml) в аддоне ESPHome Builder (через Supervisor, как сам HA), положит .ota.bin в папку прошивок и прошьёт датчик: в сервисном режиме — сразу по Wi-Fi, иначе по BLE в ближайшее окно (оборвался Wi-Fi — продолжит по BLE). То же — сервис move_sensor_ble_ota.build_and_flash или POST /api/move_sensor_ble_ota/build. Снаружи HA — скрипт /config/esphome/tools/ble_ota_flash.py.
Вручную, своим файлом
  1. В ESPHome: Install → Manual download → OTA format (*.ota.bin). Подойдёт и factory.bin — приложение вырежется само.
  2. Настройки → Устройства и службы → Move Sensor BLE OTA → Настроить → «Загрузить прошивку (.bin)».
  3. Выбрать файл, оставить галочку «Сразу запустить прошивку по BLE».
  4. Дождаться пробуждения датчика (или помахать рукой). ~7 КБ/с через прокси — образ 1,25 МБ ≈ 3 мин.
Ход прошивки (сущность «Firmware», атрибуты /status)
idle→ building %→ waiting→ connecting→ flashing %→ success
errorcancelled
building — только при сборке («Установить», build_and_flash). После сборки ключ OTA в образе сверяется с ключом интеграции — не совпал → ошибка, прошивка не начинается. Отмена — служба move_sensor_ble_ota.cancel или кнопка на панели. После success — сразу idle и 0 %, как только датчик ответил новой версией (запасной таймер 2 мин). Обрыв связи → waiting, повтор в следующее окно.
По воздуху меняется только приложение. Таблица разделов (partitions_c3_4mb.csv) — только по USB. Первую прошивку с поддержкой BLE OTA тоже залить по USB или Wi-Fi (сервисный режим).

Панель (v1.20)

Панель Move Sensor BLE в боковом меню — три таба, только стандартные карточки Home Assistant (tile с элементами управления, значки, график истории). Ничего доустанавливать не нужно.

С v1.24 тексты панели (табы, заголовки, подсказки, «Требует внимания») идут на языке Home Assistant (Профиль › Язык): русский, украинский, для остальных — английский. Имена сущностей остаются английскими.

ТабЧто там
OverviewЗначки: связь, сигнал, когда был на связи, статус настроек. «Needs attention» появляется, только если что-то не так (батарея садится, нет данных, движение залипло, новая прошивка, настройки не приняты). Четыре карточки: Motion, Temperature, Humidity, Battery. Нажатие на карточку (или шестерёнку) — шторка с историей за сутки и настройками этой величины; на телефоне она выезжает снизу и поднимается над клавиатурой. Долгое нажатие — стандартное окно Home Assistant (полная история, статистика); его же открывает иконка графика в шторке.
SettingsПовседневные настройки в трёх группах: Motion (Keep time, Motion LED), Temperature & humidity (Report interval), Battery (Capacity, Low level). Редкие (Detect delay, поправки) — под «Show more». Числа меняются кнопками − / +, порог — слайдером; вводом с цифровой клавиатуры — только ёмкость.
AdvancedСвёрнутые разделы: Firmware (установка, сборка, резервная копия, откат, отмена), Bluetooth (сигнал, окна, Identify), Wi-Fi (сервисный режим, только когда он включён), Calibration (коэффициент напряжения, PIR stuck after), Diagnostics. Необратимые действия (откат, сброс Wi-Fi) просят подтверждения. Новая сущность интеграции без своего места попадает в Diagnostics.

Сколько считать «нет данных»: интеграция → Настроить → Параметры → «Сообщать, если нет данных»: Авто (3 × интервал климата, не меньше 15 мин) или 10 мин … 2 ч. Не короче двух интервалов климата — спящий датчик не даёт ложных тревог. Если отчёты климата выключены (интервал 0), без движения датчик может молчать часами — тогда уведомления нет. Пока датчик молчит, «движение залипло» не сообщается: «занято» — это просто его последняя посылка.

Каждое новое уведомление ещё и событие move_sensor_ble_ota_issue (issue, name, address и числа из текста) — повесьте на него автоматизацию с пушем на телефон.

Малополезные сущности при новой установке выключены: Signal в дБм (Signal level в % остаётся), BLE TX power, счётчики brownout и сбоев. Нужны — включите в настройках сущности.

Перенос на новый Home Assistant

Через полный бэкап HA — проще всего
  1. Старый HA: Настройки → Система → Резервные копии → полная копия.
  2. Новый HA: при первом запуске «Восстановить из резервной копии».
  3. Переедет всё: папка интеграции, запись с адресом и ключом, сохранённые настройки (.storage/move_sensor_ble_ota.*), прошивки в /config/esphome/ota, secrets.yaml.
  4. Проверить, что Bluetooth-прокси ESPHome подключён к новому HA и датчик виден.
Начисто, без бэкапа
  1. Подключить к новому HA Bluetooth-прокси (интеграция ESPHome). Интеграция BTHome не нужна.
  2. Установить интеграцию — из Marketplace или вручную (раздел «Установка»).
  3. Ключ: перенести строку move_sensor_ble_ota_key в /config/esphome/secrets.yaml нового HA или вписать его при добавлении. Без него датчик не пустит («нет авторизации»).
  4. Добавить интеграцию с тем же Bluetooth-адресом. Настройки прочитаются с датчика при первом пробуждении.
Ключ — единственное, что нельзя восстановить с датчика. Храни его вместе с ESPHome-конфигами. Если ключ потерян — сменить его в secrets.yaml и залить прошивку по USB или Wi-Fi (сервисный режим).

Сущности

v1.15: одно устройство Move Sensor BLE — данные и настройки датчика независимо от канала (BLE или Wi-Fi). Копии в ESPHome-устройстве и BTHome (если он добавлен) скрыты (не выключены). Панель Move Sensor BLE в боковом меню.

Прошивка

FirmwareupdateВместо Flash / Build & flash / Cancel / OTA status / OTA progress / Firmware version. В «Обновлениях» — «Move Sensor BLE firmware»: установлена «build 16.11 13:48», новая «new build · YAML changed …». «Установить» — сборка, проверка ключа OTA, прошивка по Wi-Fi сразу (сервисный режим) или по BLE в ближайшее пробуждение; оборвался Wi-Fi — продолжит по BLE; переживает перезапуск HA; та же сборка, что уже на датчике, повторно не шьётся; Last flash — время, канал, длительность, скорость; «Примечания к выпуску» — какие файлы прошивки изменены с прошитой сборки и построчный diff (secrets.yaml не показывается, ключи и пароли — ***). Версия прошивки и «что нового» — из esphome/move_sensor_ble/CHANGELOG.md (разделы «## 1.4.0 — дата» с «Добавлено / Исправлено / Изменено», как у аддонов): показываются разделы, которых не было в прошитой сборке; нет записи — короткий пересказ «параметр: было → стало». Правка только CHANGELOG новую прошивку не предлагает. С прошивки 1.4.0 версию сообщает сам датчик (по BLE, «1.4.0 v…»): «что нового» — все разделы CHANGELOG новее неё. Пароль ESPHome OTA для прошивки по Wi-Fi (прошивка 1.4.0+) интеграция берёт из move_sensor_ota_password в secrets.yaml. Прошивка «Установить» в самом ESPHome Builder ключ не проверяет. На панели в разделе Firmware (v1.18.1): OTA status — этап на всех шагах («Building 37 %», «Waiting for sensor wake», «Connecting», «Flashing 70 %», «Success», «Error: …», «Idle»; у самой «Firmware» процент виден только во время прошивки); кнопки Install (сборка и прошивка с резервной копией, с подтверждением), Build (только собрать — проверка конфига без прошивки), строка Backup (последняя копия) и Roll back (прошить её обратно, с подтверждением), Cancel. После прошивки версия в «Firmware» обновляется сразу, как датчик её сообщил

PIR stuckbinary«Занято», и свежих срабатываний нет дольше порога PIR stuck after (человек шевелится рядом — не проблема; у прошивки до 2026-11-16 — просто «занято» дольше порога): обрыв провода PIR, тепло/солнце в линзе, просадка питания
Имена BTHomeauto«Count» → Wake count (с v1.14.2 застыл: Wake count едет в своём блоке рекламы), бинарная «Батарея» → Battery low (с v1.14.2 не передаётся). Только имя (entity_id прежний) и только если не переименовано вручную
Brownout countsensorПерезагрузки по просадке питания — конец разряда или просадка под радио
Crash countsensorСбои прошивки: panic + watchdog (подробно — в атрибутах)
Last reset reasonsensorПричина последней загрузки «не из сна»: power on, brownout, software, panic…

Защита и надёжность

HMAC-ключmove_sensor_ble_ota_key из esphome/secrets.yaml; одноразовый nonce
Только свой образсверка project_name; CRC-32 и проверка ESP-IDF
Порог батареиниже 30 % OTA отклоняется
Откатне прошла safe_mode 15 с — загрузчик вернёт старую
Резервная копия и откат (v1.18). В окне обновления «Firmware» есть ссылка «Список изменений» (CHANGELOG прошивки на GitHub) и галочка «Резервная копия»: перед сборкой прошивка, что сейчас на датчике, и копия её YAML сохраняются в <папка прошивок>/backup/ (последние 3, уборка .bin их не трогает). Если образа текущей прошивки в папке нет (прошит из ESPHome Builder или удалён уборкой) — «Установить» с галочкой остановится с ошибкой. Откат — сервис move_sensor_ble_ota.rollback: тем же путём (Wi-Fi в сервисном режиме, иначе BLE), после него «Firmware» снова предложит текущий YAML. Атрибут backup — какая копия последняя.

Протокол GATT

Сервис 6d730001-626c-6f74-4d6f-766553656e73. Все числа little-endian.

ХарактеристикаКоманды
…0002 CTRL
write + notify		 HELLO nonce · AUTH HMAC · INFO версия · GET/SET настройки · BEGIN размер+CRC · STATUS · END · ABORT
…0003 DATA
write without response		 offset:u32 + данные (≤ 240 Б), блоки 4096 Б, после каждого — ACK в CTRL; каждый 4-й пакет с подтверждением

Полное описание — в шапке components/bthome/ble_ota.h (прошивка) и const.py (интеграция).

Диагностика

Долго waitingДатчик не просыпается или прокси его не слышит. Помахать рукой; проверить, что прокси с bluetooth_proxy: (активные подключения) рядом.
Цикл connecting → flashing → waitingДатчик рвёт связь. Смотреть лог датчика в сервисном режиме (тег ble_ota) — там причина.
Settings status: error«неверное состояние/команда» — на датчике прошивка без команд настроек. Неверный ключ — «нет авторизации».
«батарея ниже порога»Зарядить датчик или поменять min_battery в YAML.
